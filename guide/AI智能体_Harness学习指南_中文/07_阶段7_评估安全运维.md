# 阶段 7:评估·安全·运维 ── production 化

> [← 06 工作流 vs 智能体](06_阶段6_工作流与智能体.md) ｜ [08 走向框架 →](08_阶段8_框架.md)

把智能体从「能跑」变为「能放心交付」,就是本阶段。

## 7-1. 讲解

### 安全(Safety)的多层防御

production Harness 叠加**多个相互独立的安全层**(一层被攻破,其他层仍守住)。

- **审批门(approval)**:高风险操作(删除·转账·外发)前先向人确认。
- **危险命令检测**:检测并拦截 `rm -rf /` 之类命令。
- **hooks(钩子)**:在工具执行前后插入检查逻辑。
- **stale-read 检测**:防止用陈旧的读取结果去写入。
- **plan mode 限制**:规划阶段不允许使用写入工具。
- **doom loop 检测**:检测并停止反复同一失败的死循环。
- **iteration cap**:迭代上限(阶段 2 已实现)。
- **cooperative cancellation**:用户随时可中断。

### 评估(Eval)

把「智能体是否正确运作」变得**可测量**。

- **ground truth 验证**:每步都有可与「正解」比对的机制(如测试是否通过)。
- **sandbox 充分测试**:投入 production 前在安全隔离环境反复验证。
- **eval 集**:收集「输入 → 期望输出」对的评估数据集,每次改动都测正确率。没有它就无法察觉「自以为改善实则恶化」。
- **持续度量与迭代**:持续度量性能,基于结果改进。

### 可观测性(Observability)

- 详尽日志·行为日志(episodic memory)·审计轨迹。
- 能事后追踪「智能体想了什么、做了什么、观察到什么」。这是故障分析与改进的前提。

### 授权·权限(Authorization)

- 结构化的授权层、intent-based(基于意图)的强制、合规审计轨迹。
- 新兴标准:**MCP**(工具/数据连接,阶段 9)、**A2A**(智能体间路由,阶段 10)、**Open Agent Passport**(事前授权 + 审计)。

### 模型与 Harness 的协同进化(进阶)

LangChain 指出:把模型与 Harness 一起做后训练(post-training),native 能力会提升,但也可能对特定任务过拟合(overfitting)。而**Harness 侧的优化,与模型代际无关地提升性能**。因此 Harness 工程(harness engineering)作为独立学科日益重要。

## 7-2. 示例代码 ── 护栏 + 简易 eval

```python
import re
import subprocess

# ── 危险命令检测护栏 ──
DANGEROUS_PATTERNS = [
    r"rm\s+-rf\s+/",          # 删除根目录
    r"DROP\s+TABLE",          # 删表
    r":\(\)\{.*\};:",         # fork bomb
]
def is_dangerous(command):
    return any(re.search(p, command, re.IGNORECASE) for p in DANGEROUS_PATTERNS)

def safe_run_bash(command):
    if is_dangerous(command):
        return f"⛔ 作为危险命令拦截: {command}"
    # 审批门(高风险操作向人确认)
    if any(w in command for w in ["delete", "drop", "remove", "format"]):
        approved = input(f"是否执行以下命令? [y/N]: {command}\n> ")
        if approved.lower() != "y":
            return "用户拒绝了执行"
    return subprocess.run(command, shell=True, capture_output=True, text=True).stdout


# ── 用简易 eval 集度量正确率 ──
# 事先准备固定的测试用目录 /work:
#   /work/config.json … {"port": 8080}
#   /work/readme.txt  … "版本: 1.2.0"
EVAL_SET = [
    {"input": "在 /work 下找到配置文件并告诉我端口号", "expect_contains": "8080"},
    {"input": "/work 的 readme 里写的版本是?",          "expect_contains": "1.2.0"},
    {"input": "列出 /work 下的文件",                     "expect_contains": "config.json"},
]
def evaluate_agent(agent_fn):
    passed = 0
    for case in EVAL_SET:
        output = agent_fn(case["input"])
        ok = case["expect_contains"] in output
        passed += ok
        print(f"{'✅' if ok else '❌'} {case['input']} → 期望:{case['expect_contains']}")
    print(f"\n正确率: {passed}/{len(EVAL_SET)} = {passed/len(EVAL_SET)*100:.0f}%")
    return passed / len(EVAL_SET)

# 用法: evaluate_agent(run_agent)  ← 评估阶段2的智能体
```

## 7-3. 练习

1. **【实现】** 给 `is_dangerous` 增加 3 条模式(如 `sudo`、`> /dev/sda`、`chmod 777 /`)。说明各自防的是什么。
2. **【实现】** 对阶段 2 的智能体,把 `EVAL_SET` 增到 10 条,用 `evaluate_agent` 度量正确率。再改善工具描述,看正确率能否提升(=eval 驱动的改进)。
3. **【理解】** 「审批门」与「危险命令检测」都是安全装置,但职责不同。分别说明各自守护什么、为何两者都需要(多层防御的意义)。
4. **【设计】** 假设要把你的智能体公开给公司内部,设计所需的可观测性(observability)。该记录什么日志(输入·思考·工具调用·结果·错误·耗时等),以及如何用于故障分析。
5. **【项目联动】** 把本项目的「绝对禁止 Top 10」「AI 投入禁止领域(§5)」「权限模式」对应到 7-1 的安全层。从 eval「不让看答案」的角度,说明为何不让 AI 读 `21_納品済_調達_新システム/`。
6. **【综合·毕业练习】** 把阶段 2~7 做的零件(ReAct 循环·工具·compaction·护栏·eval)整合进一个 `AgentHarness` 类,完成「调查指定文件夹内文本文件、生成总结报告」的智能体。这是本教科书的毕业练习。(阶段 10 会把它多智能体化)
