# 阶段 6:工作流 vs 智能体 / 多智能体入门

> [← 05 Harness 九大组件](05_阶段5_Harness九大组件.md) ｜ [07 评估·安全·运维 →](07_阶段7_评估安全运维.md)

## 6-1. 讲解

### 最重要的区分:工作流 与 智能体

Anthropic 把 agentic system 分为两类。

| | 定义 | 控制主体 |
|---|---|---|
| **Workflow(工作流)** | LLM 与工具沿**预先定义的代码路径**编排 | 开发者(代码) |
| **Agent(智能体)** | LLM **自行动态决定流程与工具使用** | 模型 |

工作流「确切地完成既定步骤」,智能体「灵活应对不可预测的问题」。不是谁更优,而是**按问题来选**。

### 铁律:先简单

> **从最简单的方案开始,只在必要时增加复杂度。**

智能体化(自主循环)是用「性能」换取延迟和成本。若简单的工作流或单次 API 调用就够,那就够了。**不是「因为想做成智能体」,而是「因为简单方法明显不够」**才加复杂度,这才是正确顺序。

### 5 种工作流模式

所有复杂系统都能用这 5 种模式的组合来解释。

**1. Prompt Chaining(串联)**
把任务拆成顺序步骤,每次 LLM 调用处理上一步的输出。适合可固定拆分的任务。
*例*:写营销文案 → 再翻译成另一种语言。

**2. Routing(路由)**
对输入分类,分派到专门的下游处理。当不同类别适合不同 prompt·不同工具时有效。
*例*:客服中把「退货」「技术问题」「账单」分到不同处理器。

**3. Parallelization(并行化)**
- *sectioning*:把独立子任务拆开同时执行。
- *voting*:对同一问题多次尝试、以多数表决提升置信度。
*例*:护栏(主处理与安全检查并行)、代码评审的多视角。

**4. Orchestrator-Workers(编排者 + 工人)**
中央 LLM 把**事先无法预测**的子任务动态分解,委派给专门 worker 并聚合结果。
*例*:跨多个文件的代码改动(改哪些文件只有运行时才知道)。

**5. Evaluator-Optimizer(评估者 + 优化者)**
一个 LLM 生成,另一个评估·反馈,循环往复。当有明确评估标准、迭代改善能带来可测量价值时有效。
*例*:生成翻译 → 评估者指出「这里不自然」→ 修改,如此反复。

> 多智能体(多个自主智能体的协作)是这些模式的发展。正式模式(Supervisor / A2A / handoff 等)在 **阶段 10** 讲解。

### 智能体成功的 3 原则

1. **Simplicity(简单)**:不引入不必要的复杂度。
2. **Transparency(透明)**:显式展示规划步骤(让用户知道将发生什么)。
3. **工具文档化·测试**:对 ACI 投入与 HCI 同等的精力(阶段 3)。

## 6-2. 示例代码 ── 各模式的最小实现

```python
# ask() 设为「单次裸模型调用、返回文本」的辅助函数
# 事先: client = InferenceClient(api_key=os.environ["HF_TOKEN"])
def ask(prompt):
    r = client.chat.completions.create(model="Qwen/Qwen2.5-72B-Instruct", max_tokens=1024,
                                       messages=[{"role": "user", "content": prompt}])
    return r.choices[0].message.content

# ── 1. Prompt Chaining(串联)──
def chain(topic):
    draft = ask(f"为 {topic} 写 3 句宣传文案")              # 步骤1
    polished = ask(f"把下面的文案翻译成英文:\n{draft}")       # 步骤2(用上一步输出)
    return polished

# ── 2. Routing(路由)──
def route(query):
    category = ask(f"把下面分类为「退货/技术/账单」,仅输出词:\n{query}")
    handlers = {"退货": handle_return, "技术": handle_tech, "账单": handle_billing}
    return handlers.get(category.strip(), handle_default)(query)

# ── 3. Parallelization / voting(多数表决)──
from concurrent.futures import ThreadPoolExecutor
def vote(question, n=3):
    with ThreadPoolExecutor() as ex:
        answers = list(ex.map(lambda _: ask(question), range(n)))
    # 采用出现最多的回答(简易)
    return max(set(answers), key=answers.count)

# ── 4. Orchestrator-Workers(编排者+工人)──
import json
def orchestrate(task):
    subtasks = ask(f"把下面任务分解成独立子任务的列表(JSON数组):\n{task}")
    subtasks = json.loads(subtasks)
    with ThreadPoolExecutor() as ex:
        results = list(ex.map(lambda st: ask(f"执行下面:{st}"), subtasks))  # worker
    return ask(f"整合下面的部分结果,做成最终成果物:\n{results}")            # 聚合

# ── 5. Evaluator-Optimizer(评估者+优化者)──
def evaluate_optimize(task, max_rounds=3):
    result = ask(f"执行下面:{task}")
    for _ in range(max_rounds):
        critique = ask(f"评估下面成果物,有问题就列出,没有则输出 'OK':\n{result}")
        if "OK" in critique[:5]:
            break
        result = ask(f"根据下面意见改善:\n成果物:{result}\n意见:{critique}")
    return result
```
