## 前言 ── 本教科书的阅读方法

学习 AI 智能体时,很多人从「给 ChatGPT 那样聪明的 AI 加上工具」这种模糊印象出发。但这样无法理解智能体为何时常表现异常,也无法理解为何「上下文管理」如此重要。

本教科书把**明确区分「模型(大脑)」和「Harness(底层支撑)」**作为最高方针。模型很聪明,但它只是一个生成文本的存在。把它变成能够「读取文件、执行命令、完成多步骤工作」的智能体的,正是 Harness 这一外层。

```
┌─────────────────────────────────────────┐
│  Harness = 智能体的底层支撑层             │
│  ┌───────────────────────────────────┐  │
│  │  模型 (LLM) = 引擎·大脑            │  │  ← 聪明,但只会生成文本
│  └───────────────────────────────────┘  │
│  工具执行·上下文管理·权限控制·记忆·循环    │  ← 这里才是「智能体化」的层
└─────────────────────────────────────────┘
```

各章按「讲解 → 示例代码 → 练习」的顺序推进。**练习请务必动手完成**。智能体开发只靠阅读绝对学不会。特别是阶段 2 的「自己写一条智能体循环」,是本教科书中最重要的经验。

### 学习顺序

```
F1 LLM基础 → F2 ReAct循环自写(最重要) → F3 工具设计 → F4 上下文工程
   → F5 Harness九大组件 → F6 工作流/智能体 → F7 评估·安全·运维
   → F8 框架 → F9 MCP → F10 多智能体 → 毕业
```

> 铁律(全章通用):**先用裸 API 写循环 → 框架放在后面**。先亲身体会「为什么需要它」,再走向抽象。

### 代码如何层层叠加

代码示例会跨章节层层叠加。阶段 2 自写的循环,在阶段 4 加上 compaction、阶段 5 加上护栏,**在阶段 7 的毕业练习中整合进一个 `AgentHarness` 类**,再**在阶段 10 多智能体化**。

### 把本项目当作教材使用

各章末尾的「项目联动」练习中,你将把手头的实物 ── `CLAUDE.md` / `共通規約/` / `memory/` / Skill 群 / Workflow 工具 / `mcp__*` 工具 ── 对应到所学理论的哪一部分。这是连接理论与实际运维 Harness 的入口。
