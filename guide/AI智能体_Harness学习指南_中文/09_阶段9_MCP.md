# 阶段 9:MCP ── 工具连接的标准协议

> [← 08 走向框架](08_阶段8_框架.md) ｜ [10 多智能体 →](10_阶段10_多智能体.md)

## 9-1. 讲解

### 何为 MCP ── 「AI 的 USB-C」

阶段 3 中,工具是一个个手写定义的。但现实里要连 GitHub·Slack·PostgreSQL·Stripe… 无数外部服务。逐服务·逐框架地写连接方式没完没了。

**MCP(Model Context Protocol)** 就是把这「AI 应用 ↔ 外部工具/数据」的连接**标准化**的开放协议。由 Anthropic 于 2024 年 11 月公开,如今 OpenAI·Google 也支持,已成事实标准。常被喻为「**AI 的 USB-C**」── 一次做好 MCP 服务器,所有支持 MCP 的客户端(Claude Desktop·Claude Code·Cursor·VS Code…)都能立即使用。

> 普及情况(2026 Q2):GitHub·Slack·PostgreSQL·Stripe·Figma·Docker·Kubernetes 等 200 多个社区 MCP 服务器存在。约 28% 的 Fortune 500 已在其 AI 栈中部署 MCP 服务器。

### 架构 ── 客户端·服务器型

MCP 建立在 **JSON-RPC 2.0** 之上,为客户端·服务器型。

```
┌─────────────── Host(Claude Code / Cursor / Claude Desktop)──────────────┐
│  ┌── MCP Client A ──┐   ┌── MCP Client B ──┐   ┌── MCP Client C ──┐     │
└──┼──────────────────┼───┼──────────────────┼───┼──────────────────┼─────┘
   │ JSON-RPC         │   │ JSON-RPC         │   │ JSON-RPC         │
┌──▼─────────────┐  ┌───▼────────────┐  ┌────────▼───────────┐
│ MCP Server     │  │ MCP Server     │  │ MCP Server         │
│ (GitHub)       │  │ (PostgreSQL)   │  │ (公司内 API)       │
└────────────────┘  └────────────────┘  └────────────────────┘
```

- **Host**:AI 应用本体(汇集多个 MCP 客户端会话)。
- **MCP Client**:与 1 个服务器 1:1 相连的、有状态的 JSON-RPC 通道。
- **MCP Server**:「提供」工具或数据的一方。你来做 / 用现成的。

### MCP 服务器公开的 3 种原语

| 原语 | 含义 | 与阶段 3·4 的对应 |
|---|---|---|
| **Tools(工具)** | 带副作用的执行操作(插入 DB 行·发邮件·调 API) | 阶段 3 的工具本身 |
| **Resources(资源)** | 只读的数据访问(文件内容·DB 内容) | 阶段 4 JIT retrieval 的来源 |
| **Prompts(提示词)** | 引导用户工作流的预定义模板 | 可复用的指令零件 |

### 传输方式(transport)2 种

- **stdio**:作为本地子进程通信。适合桌面应用与开发。
- **HTTP / SSE(Streamable HTTP)**:远程、可扩展的连接。适合云部署·微服务。2026 年这一 remote 化推动了 production 普及(但有状态会话与负载均衡的兼容性等问题仍存)。

### 与本会话的关系

你所在的环境已连接了大量 MCP 工具。开头「deferred tools」清单 ── `mcp__Claude_in_Chrome__*`(浏览器操作)、`mcp__scheduled-tasks__*`(调度)、`mcp__ccd_session__*`(会话管理)等 ── **全是经 MCP 服务器提供的工具**。`mcp__<服务器名>__<工具名>` 的命名,也正是阶段 3 所学命名空间的实例。

## 9-2. 示例代码 ── 做一个最小 MCP 服务器

用 Python 官方 SDK(`mcp`)把阶段 3 的「计算器」作为 MCP 服务器公开。

```python
# pip install mcp
# server.py ── 提供计算器的 MCP 服务器
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("calculator-server")

@mcp.tool()                              # ← Tools 原语
def calculate(expression: str) -> str:
    """计算表达式并返回结果。例: '1+2*3'"""
    return str(eval(expression))          # 仅学习用,生产勿用 eval

@mcp.resource("config://version")        # ← Resources 原语(只读)
def version() -> str:
    """返回本服务器的版本。"""
    return "1.0.0"

if __name__ == "__main__":
    mcp.run(transport="stdio")            # ← 以 stdio 传输启动
```

把它注册到 Claude Desktop / Claude Code 的配置文件,即可立刻当工具使用(示意):

```json
{
  "mcpServers": {
    "calculator": {
      "command": "python",
      "args": ["C:/path/to/server.py"]
    }
  }
}
```

注册后,AI 侧就能看到 `calculate` 工具,像阶段 3 手写定义那样调用 ── 但**今后任何客户端都能复用**,这是决定性差别。

## 9-3. 练习

1. **【理解】** 解释「AI 的 USB-C」这一比喻的含义,与阶段 3 一个个定义工具的经历作对比。
2. **【辨识】** 从本会话的 deferred tools 清单中举出 5 个经 MCP 的工具,提取 `mcp__<服务器名>__<工具名>` 的服务器名部分。说明命名空间(阶段 3)如何发挥作用。
3. **【设计】** 为 Tools·Resources·Prompts 三种原语各想 2 个具体例子。「获取天气预报」「查阅公司考勤规章」「代码评审用模板」分别属于哪一种?
4. **【实现】** 实际运行上面的 `server.py`,增加 `read_file` 工具和「返回当前时间的 resource」。可能的话注册到 Claude Desktop 或 Cursor 并调用。
5. **【进阶】** 从本地开发与云部署的角度,说明 stdio 与 HTTP 传输的取舍。说明扩展 remote MCP 时的问题(有状态会话 × 负载均衡)。
6. **【项目联动】** 若要为本采购 PoC 做一个「检索业务 SQL 的 MCP 服务器」,设计把什么分配给 Tools·Resources·Prompts(提示:SQL 执行=Tool、查阅 `棚卸し.md`=Resource、生成行映射注释=Prompt)。
