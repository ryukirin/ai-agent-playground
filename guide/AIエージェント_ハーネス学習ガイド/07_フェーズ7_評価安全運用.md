# フェーズ 7:評価・安全・運用 ── production 化

> [← 06 ワークフロー vs エージェント](06_フェーズ6_ワークフローvsエージェント.md) ｜ [08 フレームワークへ →](08_フェーズ8_フレームワーク.md)

エージェントを「動く」状態から「安心して任せられる」状態にするのがこのフェーズです。

## 7-1. 解説

### 安全(Safety)の多層防御

production ハーネスは、**独立した複数の安全層**を重ねます(一つが破られても他が守る)。

- **承認ゲート(approval)**:高リスク操作(削除・送金・外部送信)の前に人間に確認。
- **危険コマンド検出**:`rm -rf /` のようなコマンドを検出してブロック。
- **hooks(フック)**:ツール実行の前後に検査ロジックを差し込む。
- **stale-read 検出**:古い読み取り結果のまま書き込もうとするのを防ぐ。
- **plan mode 制限**:計画段階では書き込みツールを使わせない。
- **doom loop 検出**:同じ失敗を繰り返す無限ループを検出して止める。
- **iteration cap**:反復上限(フェーズ 2 で実装済み)。
- **cooperative cancellation**:ユーザがいつでも中断できる。

### 評価(Eval)

「エージェントが正しく動いているか」を**測定可能**にします。

- **ground truth 検証**:各ステップで「正解」と照合できる仕組みを持つ(例:テストが通るか)。
- **sandbox で徹底テスト**:production 投入前に、安全な隔離環境で繰り返し検証。
- **eval セット**:入力 → 期待出力 のペアを集めた評価データセットを作り、変更のたびに正解率を測る。これがないと「改善したつもりで悪化」に気づけません。
- **継続的計測と反復**:性能を測り続け、結果に基づいて改善する。

### 観測性(Observability)

- 詳細ログ・行動ログ(episodic memory)・監査証跡。
- 「エージェントが何を考え、何をして、何を観察したか」を後から追跡できること。障害解析と改善の前提です。

### 認可・権限(Authorization)

- 構造化された認可レイヤー、intent-based(意図ベース)の強制、コンプライアンス監査証跡。
- 新興標準:**MCP**(ツール/データ接続、フェーズ 9)、**A2A**(エージェント間ルーティング、フェーズ 10)、**Open Agent Passport**(事前認可 + 監査)。

### モデルとハーネスの共進化(発展)

LangChain の指摘:モデルをハーネスと一緒に後訓練(post-training)すると、native な能力は上がるが、特定タスクへの過学習(overfitting)も起こりうる。一方で**ハーネス側の最適化は、モデル世代に関係なく性能を上げる**。だからハーネス工学(harness engineering)が独立した規律として重要になっています。

## 7-2. 例コード ── ガードレール + 簡易 eval

```python
import re
import subprocess

# ── 危険コマンド検出ガードレール ──
DANGEROUS_PATTERNS = [
    r"rm\s+-rf\s+/",          # ルート削除
    r"DROP\s+TABLE",          # テーブル削除
    r":\(\)\{.*\};:",         # fork bomb
]
def is_dangerous(command):
    return any(re.search(p, command, re.IGNORECASE) for p in DANGEROUS_PATTERNS)

def safe_run_bash(command):
    if is_dangerous(command):
        return f"⛔ 危険なコマンドとしてブロック: {command}"
    # 承認ゲート(高リスク操作は人間確認)
    if any(w in command for w in ["delete", "drop", "remove", "format"]):
        approved = input(f"次を実行してよいですか? [y/N]: {command}\n> ")
        if approved.lower() != "y":
            return "ユーザが実行を拒否しました"
    return subprocess.run(command, shell=True, capture_output=True, text=True).stdout


# ── 簡易 eval セットで正解率を測る ──
EVAL_SET = [
    {"input": "10 と 20 を足して", "expect_contains": "30"},
    {"input": "100 を 4 で割って",  "expect_contains": "25"},
    {"input": "7 の 2 乗は",        "expect_contains": "49"},
]
def evaluate_agent(agent_fn):
    passed = 0
    for case in EVAL_SET:
        output = agent_fn(case["input"])
        ok = case["expect_contains"] in output
        passed += ok
        print(f"{'✅' if ok else '❌'} {case['input']} → 期待:{case['expect_contains']}")
    print(f"\n正解率: {passed}/{len(EVAL_SET)} = {passed/len(EVAL_SET)*100:.0f}%")
    return passed / len(EVAL_SET)

# 使い方: evaluate_agent(run_agent)  ← フェーズ2のエージェントを評価
```

## 7-3. 課題

1. **【実装】** `is_dangerous` にパターンを 3 つ追加せよ(例:`sudo`、`> /dev/sda`、`chmod 777 /`)。それぞれが何を防ぐか説明せよ。
2. **【実装】** フェーズ 2 のエージェントに対して `EVAL_SET` を 10 件に増やし、`evaluate_agent` で正解率を測れ。次にツールの説明文を改善して、正解率が上がるか実験せよ(=eval 駆動の改善)。
3. **【理解】** 「承認ゲート」と「危険コマンド検出」は両方とも安全装置だが、役割が違う。それぞれが何を守り、なぜ両方必要か(多層防御の意義)を説明せよ。
4. **【設計】** あなたのエージェントを社内に公開するとして、必要な observability(観測性)を設計せよ。何をログに残すべきか(入力・思考・ツール呼び出し・結果・エラー・所要時間など)を列挙し、障害解析にどう使うか述べよ。
5. **【プロジェクト連動】** このプロジェクトの「絶対禁止トップ 10」「AI 投入禁止領域(§5)」「権限モード」が、7-1 の安全層のどれに当たるか対応づけよ。`21_納品済_調達_新システム/` を AI に読ませない理由を、eval の「答えを見せない」観点から説明せよ。
6. **【総合・卒業課題】** フェーズ 2〜7 で作った部品(ReAct ループ・ツール・compaction・ガードレール・eval)を 1 つの `AgentHarness` クラスに統合し、「指定フォルダ内のテキストファイルを調査して要約レポートを作る」エージェントを完成させよ。これがこの教科書の卒業課題である。(フェーズ 10 でこれをマルチエージェント化する)
