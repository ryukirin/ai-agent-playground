## 8-1. 解説

### なぜ「自作してから」フレームワークなのか

フェーズ 2〜7 で、ReAct ループ・ツール実行・compaction・ガードレールを**手で書いて**きました。これは遠回りに見えて、実は最短ルートです。フレームワークは「これらを自動でやってくれる箱」ですが、中身を知らずに使うと、エラーが出たときに何が起きているか分からず詰みます。Anthropic も「まず直接 API 呼び出しから始め、フレームワークは仕組みを理解してから」と明言しています。

つまりフレームワークの価値は、**あなたが手で書いたものを「設定」や「数行」に置き換えてくれる**点にあります。何を置き換えているかが見えていれば、選定も使いこなしも容易になります。

### 主要フレームワークの地図(2026 年)

| フレームワーク | 提供元 | 特徴 | モデル依存 |
|---|---|---|---|
| **Claude Agent SDK** | Anthropic | 「エージェントにコンピュータを与える」思想。ファイル/シェルアクセスのツールが組込済でボイラープレートが少ない。**MCP 統合が最も深い**。状態はセッション環境(ディスク上のファイル・環境変数)自体に持つ | Claude のみ |
| **LangGraph** | LangChain | グラフ(状態機械)でエージェントを定義。**チェックポイント + time travel**(過去状態に巻き戻し)、`interrupt()` による human-in-the-loop が一級市民。LangSmith で観測性。production 成熟度が最も高い | モデル非依存 |
| **OpenAI Agents SDK** | OpenAI | handoff(引き継ぎ)が一級プリミティブ。エージェント A が構造化ペイロードと共に B へ制御を渡し、遷移を記録(リプレイ可能) | OpenAI 中心 |
| **CrewAI** | CrewAI | 「役割(role)を持つエージェントのチーム」という直感的な抽象。モデル非依存 | モデル非依存 |
| **Google ADK** | Google | マルチエージェントを既定の配備形態とし、A2A プロトコルで連携 | Gemini 中心 |

> 補足:Claude Agent SDK は旧 "Claude Code SDK"。2025 年末に汎用エージェントランタイムへ進化して改名。2026 年 4 月時点で Python(`claude-agent-sdk`)と TypeScript(npm)で提供。

### 選び方の指針

- **Claude を使う / ファイル・シェル中心 / MCP を活用したい** → Claude Agent SDK(あなたが今使っている Claude Code の基盤)。
- **複雑な状態遷移・巻き戻し・人間の承認を厳密に制御したい** → LangGraph。
- **モデルを将来差し替えたい / ベンダー非依存にしたい** → LangGraph や CrewAI。
- **学習段階** → どれを選んでも、フェーズ 2〜7 の概念がそのまま対応する。

### フレームワークが「自動化してくれるもの」対応表

| あなたが手で書いたもの(フェーズ) | フレームワークでの置き換え |
|---|---|
| `for i in range(max_iterations)` の ReAct ループ(F2) | SDK が内部で回す。あなたはツールと目標を渡すだけ |
| `TOOLS` 定義 + `run_tool`(F3) | デコレータ/登録 API。`@tool` で関数を登録 |
| `compact_history`(F4) | 自動コンテキスト管理 / チェックポイント |
| `_check_safety`・承認(F5・F7) | 権限設定・hooks・`interrupt()` |
| ログ出力(F7) | LangSmith 等の観測性ダッシュボード |

## 8-2. 例コード ── 自作ループ vs フレームワーク

同じ「電卓エージェント」を、自作版とフレームワーク版で並べます。

```python
# ── 自作版(フェーズ2の再掲・要点)──────────────────
# TOOLS を定義 → run_tool を書く → while ループ → tool_result を append …(数十行)

# ── Claude Agent SDK 版(イメージ)──────────────────
# pip install claude-agent-sdk
from claude_agent_sdk import ClaudeSDKClient, tool

@tool                                  # ← F3 のツール定義+実装がこれだけに
def calculator(expression: str) -> str:
    """数式を評価して返す。例: '1+2*3'"""
    return str(eval(expression))       # 学習用。本番で eval は使わない

async def main():
    client = ClaudeSDKClient(tools=[calculator])
    # ← F2 のループ・F4 のコンテキスト管理は SDK が内部で実行
    result = await client.query("12345 と 67890 を足して 2 で割って")
    print(result)
```

```python
# ── LangGraph 版(イメージ)──────────────────────────
# pip install langgraph langchain-anthropic
from langgraph.prebuilt import create_react_agent
from langchain_anthropic import ChatAnthropic
from langchain_core.tools import tool

@tool
def calculator(expression: str) -> str:
    """数式を評価して返す。"""
    return str(eval(expression))

agent = create_react_agent(
    ChatAnthropic(model="claude-opus-4-8"),
    tools=[calculator],
    # checkpointer=... を渡せば状態保存・巻き戻しが有効化(F4/F7 を自動化)
)
result = agent.invoke({"messages": [("user", "12345 と 67890 を足して 2 で割って")]})
print(result["messages"][-1].content)
```

両方とも、**あなたがフェーズ 2 で手書きした ReAct ループを内部で回している**だけです。`create_react_agent` という名前がそれを物語っています。

1. **【対応づけ】** フェーズ 2 の自作ループのどの行が、SDK 版・LangGraph 版のどこに「消えた」(=自動化された)か対応づけよ。消えたものは「無くなった」のではなく「隠れた」だけだと説明せよ。

3. **【実装】** Claude Agent SDK または LangGraph を実際にインストールし、フェーズ 2 で作った 2 ツール(電卓・ファイル読込)をフレームワーク版で再実装せよ。自作版と行数・挙動を比較せよ。
4. **【理解】** LangGraph の「チェックポイント + time travel」は、フェーズ 4 のどのテクニック、フェーズ 5 のどの構成要素に対応するか述べよ。なぜ human-in-the-loop に有用か説明せよ。
