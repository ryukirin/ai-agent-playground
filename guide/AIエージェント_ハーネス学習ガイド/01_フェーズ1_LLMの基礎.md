# フェーズ 1:LLM の基礎 ── なぜハーネスが必要なのか

> [← 00 はじめに](00_README.md) ｜ [02 ReAct ループ →](02_フェーズ2_ReActループ.md)

## 1-1. 解説

### モデルは「次の単語を予測するだけ」

大規模言語モデル(LLM)の動作は、本質的には極めて単純です。「これまでの文章」を入力として受け取り、「次に来る確率が最も高いトークン(単語の断片)」を 1 つ出力する。それを繰り返して文章を生成しているだけです。

ここで重要な帰結が 3 つあります。

**(1) モデルはステートレスである。**
モデルは前回の会話を「覚えて」いません。チャットで会話が続いているように見えるのは、ハーネス側が**毎回、過去のやりとり全体を入力に詰め直して**いるからです。モデル自身に記憶はありません。これが後のフェーズで「メモリ」や「コンテキスト管理」が必要になる根本理由です。

**(2) モデルはコンテキストウィンドウの中しか見えない。**
モデルが一度に受け取れるトークン数には上限があります(これをコンテキストウィンドウと呼ぶ)。この窓に入らない情報は、モデルにとって「存在しない」のと同じです。100 万行のコードベースをそのまま渡すことはできません。だから「何を渡し、何を渡さないか」の取捨選択(=コンテキストエンジニアリング、フェーズ 4)が決定的に重要になります。

**(3) モデルは自分では何も実行できない。**
モデルは「ファイルを読みたい」と文章で言うことはできても、実際にファイルを読むことはできません。モデルにできるのは「テキストを出力する」ことだけ。実際にファイルを読んだり、コマンドを走らせたりするのは、ハーネスの仕事です。

### トークンとコスト

モデルへの入力(プロンプト)も出力も、すべて「トークン」で数えられ、課金されます。日本語なら 1 文字がおおむね 1〜2 トークン、英語なら 1 単語が 1〜数トークンです。長い会話を続けると、毎ターン過去全体を送り直すため、トークン消費は会話の長さに比例して増えていきます。これがエージェントのコストとレイテンシ(応答速度)を決めます。

### システムプロンプト

モデルへの入力には階層があります。最上位にあるのが**システムプロンプト**で、「あなたは○○のアシスタントです」「次のルールに従ってください」といった、振る舞いを規定する最重要の指示です。このプロジェクトの `CLAUDE.md` は、まさに Claude Code というハーネスに対するシステムプロンプト(常駐指示)の一種です。

### まとめ:なぜハーネスが要るのか

```
モデル単体     = 賢いが「記憶なし・窓の中しか見えない・実行できない」
       ↓ これを補うのがハーネス
ハーネスが足すもの:
  - 記憶を保持して毎回詰め直す      → コンテキスト管理・メモリ
  - 窓に入る分だけ取捨選択して渡す   → コンテキストエンジニアリング
  - モデルの「○○したい」を実際に実行 → ツール実行
  - これをループで回す              → エージェントループ
```

## 1-2. 例コード ── 素の API 呼び出し(ツールなし)

まずは「ツールも何もない、素のモデル呼び出し」を体験します。エージェントではなく、ただの 1 問 1 答です。

```python
# pip install anthropic が必要。環境変数 ANTHROPIC_API_KEY を設定しておく。
import anthropic

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-opus-4-8",
    max_tokens=1024,
    system="あなたは簡潔に答えるアシスタントです。",  # システムプロンプト
    messages=[
        {"role": "user", "content": "1 から 100 までの合計はいくつ?"},
    ],
)

print(response.content[0].text)
```

次に、モデルが「実行できない」ことを体感します。

```python
response = client.messages.create(
    model="claude-opus-4-8",
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "C:/data/report.txt の中身を読んで要約して。"},
    ],
)
print(response.content[0].text)
# → モデルは「ファイルにアクセスできません」と答えるしかない。
#    実際に読む手段(ツール)を与えるのが次フェーズ。
```

## 1-3. 課題

1. **【基礎】** 上の素の API 呼び出しを実際に動かし、システムプロンプトを「あなたは関西弁で答えます」に変えて、出力が変わることを確認せよ。
2. **【理解】** 同じ会話を続けたいとき、モデルはステートレスなので何を毎回送り直す必要があるか、自分の言葉で説明せよ。実際に 2 ターン目のリクエストの `messages` 配列がどうなるべきか書き出せ(1 ターン目の user・assistant・2 ターン目の user の 3 要素になるはず)。
3. **【発展】** モデルに「今日の東京の天気は?」と聞いてみよ。なぜ正確に答えられないのか、(2) のステートレス性とは別の 2 つの理由(学習データのカットオフ / 実行手段がない)を挙げて説明せよ。
