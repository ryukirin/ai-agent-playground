# RAG〜エージェント 学習プラン

> RAG基本概念は習得済み。ここから「実戦で使えるRAG」→「自律エージェント構築」まで段階的に進む。

---

## Phase 1: RAGを深める（中級）

### 1-1. Chunking戦略 - [x]
**目標：** 分割方法の違いがRAG精度にどう影響するかを体感する

| 項目 | 内容 |
|---|---|
| 学ぶこと | Fixed-size / Recursive / Semantic Chunking の3種類 |
| なぜ重要か | Chunkが大きすぎるとノイズ混入、小さすぎると文脈喪失。ここが精度の分岐点 |
| 実践課題 | 同じ文書を3種類のChunkingで分割し、同じ質問への回答精度を比較する |
| 使う技術 | LangChain TextSplitter, tiktoken |
| 完了条件 | 3種類の分割で検索結果の違いを説明できる |

### 1-2. Embeddingモデル選定 - [x]
**目標：** 埋め込みモデルの選択がRAG精度に与える影響を理解し、適切なモデルを選べるようになる

| 項目 | 内容 |
|---|---|
| 学ぶこと | OpenAI Embedding, Cohere Embed, オープンソース（multilingual-e5等）の特性比較 |
| なぜ重要か | どんなにChunkingを工夫しても、埋め込みモデルが悪ければ検索精度の上限が決まる |
| 実践課題 | 同じ文書・同じ質問で3つのEmbeddingモデルの検索精度を比較する |
| 使う技術 | OpenAI Embeddings, HuggingFace Embeddings, MTEB Leaderboard |
| 完了条件 | 日本語文書に対して最適なモデルを根拠付きで選定できる |

### 1-3. Parent-Document Retrieval - [ ]
**目標：** 「小さく検索、大きく渡す」パターンを実装する

| 項目 | 内容 |
|---|---|
| 学ぶこと | Child Chunk で検索 → Parent Document をLLMに渡す二段構え |
| なぜ重要か | 小さいChunkは検索精度が高いが、LLMに渡す文脈が不足する。このジレンマを解決する |
| 実践課題 | 通常RAGとParent-Document Retrievalの回答を同じ質問で比較する |
| 使う技術 | LangChain ParentDocumentRetriever, ChromaDB or FAISS |
| 完了条件 | 通常RAGでは答えられないが、Parent-Documentなら答えられる質問例を作れる |

### 1-4. Hybrid Search（BM25 + Semantic） - [ ]
**目標：** キーワード検索とベクトル検索を組み合わせ、片方では拾えないケースをカバーする

| 項目 | 内容 |
|---|---|
| 学ぶこと | BM25（キーワード）とベクトル検索の得意・不得意、Reciprocal Rank Fusion による統合 |
| なぜ重要か | 固有名詞やコード片はキーワード検索が強く、意味的な質問はベクトル検索が強い。片方だけでは漏れが出る |
| 実践課題 | 同じ質問セットに対し「BM25のみ」「Semanticのみ」「Hybrid」の検索結果を比較する |
| 使う技術 | LangChain EnsembleRetriever, rank_bm25 |
| 完了条件 | Hybrid Searchでのみ正しく検索できる質問例を示せる |

### 1-5. Reranking（Cross-Encoder） - [ ]
**目標：** 検索結果をLLM/Cross-Encoderで再採点し、上位の精度を上げる

| 項目 | 内容 |
|---|---|
| 学ぶこと | Bi-Encoder（検索用）とCross-Encoder（精密採点用）の違い、2段階パイプライン |
| なぜ重要か | 検索で50件取得 → Rerankで上位5件に絞る。この一手で回答精度が最も効率よく上がる |
| 実践課題 | Reranking有無でRAGの回答精度を比較する |
| 使う技術 | Cohere Rerank or cross-encoder/ms-marco-MiniLM |
| 完了条件 | Rerankingで検索上位の関連度が改善することを数値で示せる |

### 1-6. Lost in the Middle 対策 - [ ]
**目標：** コンテキスト内の情報配置が回答精度に与える影響を理解する

| 項目 | 内容 |
|---|---|
| 学ぶこと | LLMはコンテキストの「最初」と「最後」に注意力が集中し、中間を忘れる現象 |
| なぜ重要か | 検索結果の並べ方だけで正答率が大きく変わる |
| 実践課題 | 検索結果10件を「関連度順」「重要情報を先頭/末尾に配置」で比較実験 |
| 使う技術 | LangChain LongContextReorder |
| 完了条件 | 配置順序を変えるだけで回答が改善する実例を示せる |

### 1-7. Query Transformation（HyDE / Multi-Query） - [ ]
**目標：** ユーザーの曖昧な質問を検索しやすい形に変換する技術を実装する

| 項目 | 内容 |
|---|---|
| 学ぶこと | HyDE（仮回答で検索）、Multi-Query（質問を複数に展開）、Step-Back Prompting（抽象化して検索） |
| なぜ重要か | ユーザーの質問はそのまま検索に使うには曖昧すぎることが多い。変換だけで検索精度が大幅に改善する |
| 実践課題 | 同じ質問を「そのまま検索」「HyDE」「Multi-Query」で比較し、どの手法が効くケースを整理する |
| 使う技術 | LangChain HypotheticalDocumentEmbedder, MultiQueryRetriever |
| 完了条件 | 各手法が有効なケースと逆効果なケースを説明できる |

### 1-8. Adaptive RAG - [ ]
**目標：** 質問の種類に応じて「検索する/しない」を判断するルーターを作る

| 項目 | 内容 |
|---|---|
| 学ぶこと | 質問分類（事実質問 / 意見質問 / 計算問題）→ 検索要否の判定 |
| なぜ重要か | 全ての質問にRAGを使うと遅延・ノイズ・コスト増。不要な検索を省く判断力が必要 |
| 実践課題 | LLMで質問を分類し、「RAG経由」「直接回答」「Web検索」に振り分けるルーターを実装 |
| 使う技術 | LangGraph（ここで初めて触れる）, Pydantic |
| 完了条件 | 3種類の質問を正しく振り分けるルーターが動く |

## Phase 2: エージェント構築（上級）

> Phase 1 の Adaptive RAG で LangGraph に触れた状態からスタート

### 2-1. LangGraph 基礎 - [ ]
**目標：** 状態管理付きのグラフ構造でワークフローを組む

| 項目 | 内容 |
|---|---|
| 学ぶこと | State / Node / Edge / Conditional Edge の4概念 |
| なぜ重要か | エージェントの「判断→実行→評価→分岐」をコードで表現する唯一の実用的な方法 |
| 実践課題 | Phase 1で作ったAdaptive RAGをLangGraphで書き直し、状態遷移を可視化する |
| 使う技術 | LangGraph, Mermaid（グラフ可視化） |
| 完了条件 | グラフの状態遷移図を描き、各ノードの役割を説明できる |

### 2-2. Self-Reflection（自己評価ループ） - [ ]
**目標：** エージェントが自分の出力を評価し、不十分なら再試行する仕組みを作る

| 項目 | 内容 |
|---|---|
| 学ぶこと | Generation → Grading → Re-generate のループ構造 |
| なぜ重要か | 1回で正解を出せないとき、「ダメだった」と判断して改善できるかが品質の分かれ目 |
| 実践課題 | RAGの回答に対し「根拠が十分か」「質問に答えているか」をLLMが採点し、不合格なら再検索・再生成するエージェントを作る |
| 使う技術 | LangGraph + Structured Output (Pydantic) |
| 完了条件 | 1回目で不十分な回答 → 自動で再検索 → 改善された回答、の流れが動く |

### 2-3. Error Feedback Loop（自己修復） - [ ]
**目標：** ツール実行の失敗を検知し、自動で修正・再実行する

| 項目 | 内容 |
|---|---|
| 学ぶこと | Tool呼び出し → エラー捕捉 → エラー内容をLLMに渡す → 修正案生成 → 再実行 |
| なぜ重要か | 本番環境ではAPIタイムアウト、認証切れ、データ形式の変化が日常的に起きる |
| 実践課題 | 意図的にエラーを起こすToolを作り、エージェントがエラーメッセージから復旧策を考えて再試行する仕組みを実装 |
| 使う技術 | LangGraph + Tool Calling + try/except設計 |
| 完了条件 | 3種類のエラーパターン（タイムアウト・不正入力・API制限）に自動対応できる |

### 2-4. Multi-Agent（複数エージェント協調） - [ ]
**目標：** 役割を分離した複数のエージェントが協調して1つのタスクを完遂する

| 項目 | 内容 |
|---|---|
| 学ぶこと | Supervisor / Worker パターン、エージェント間のメッセージパッシング |
| なぜ重要か | 1つの巨大Promptでは限界がある。「調査係」「執筆係」「レビュー係」に分けることで品質と信頼性が上がる |
| 実践課題 | 「リサーチャー（情報収集）」「ライター（文章生成）」「クリティック（品質チェック）」の3エージェント構成を作る |
| 使う技術 | LangGraph (Multi-Agent) |
| 完了条件 | 3エージェントが連携してレポートを生成し、品質チェックを通過する一連の流れが動く |

## Phase 3: 評価・改善（実戦レベル）

### 3-1. Ragas による RAG 評価 - [ ]
**目標：** RAGパイプラインの品質を数値で測定し、改善を回す

| 項目 | 内容 |
|---|---|
| 学ぶこと | Faithfulness（忠実度）, Answer Relevancy（回答関連性）, Context Precision（文脈精度） |
| なぜ重要か | 「なんとなく良くなった」ではなく、数値で改善を証明できなければプロダクトにならない |
| 実践課題 | Phase 1-2 で作ったRAGパイプラインに評価データセットを作り、Ragasでスコアリング。弱点を特定して改善する |
| 使う技術 | Ragas, datasets |
| 完了条件 | 改善前後のスコアを比較し、どの変更がどの指標を改善したか説明できる |

### 3-2. LangSmith によるトレース・デバッグ - [ ]
**目標：** エージェントの内部動作を可視化し、問題箇所を特定する

| 項目 | 内容 |
|---|---|
| 学ぶこと | トレース、レイテンシ分析、コスト追跡、A/Bテスト |
| なぜ重要か | エージェントが複雑になるほど「どこで何が起きたか」が見えなくなる。観測可能性は必須 |
| 実践課題 | Phase 2 のエージェントにLangSmithを接続し、各ステップの実行時間・トークン数・判断根拠を可視化する |
| 使う技術 | LangSmith |
| 完了条件 | ボトルネックを特定し、改善策を提案できる |

### 3-3. Mem0 / 長期記憶レイヤー - [ ]
**目標：** エージェントにユーザーごとの長期記憶を持たせ、パーソナライズされた応答を実現する

| 項目 | 内容 |
|---|---|
| 学ぶこと | セッションを跨ぐ記憶の保存・検索・更新、ユーザープロファイルの構造化 |
| なぜ重要か | 毎回ゼロから会話が始まるエージェントは使い物にならない。過去の文脈を覚えて初めて実用的になる |
| 実践課題 | Mem0を導入し、過去の会話履歴から嗜好を記憶 → 次の会話で活用するエージェントを作る |
| 使う技術 | Mem0, Redis or SQLite |
| 完了条件 | 2回目以降の会話でユーザーの過去の好みを踏まえた応答ができる |

## 学習の進め方

1. **各ステップは「概念理解 → 最小実装 → 実験・比較」の3段階**で進める
2. 実装は全て `rag-study/` 内にフォルダを切って保存する
3. 次のPhaseに進む前に、前のPhaseの実践課題が全て動いている状態にする
4. 分からないところは都度聞く。コードも一緒に書く

```
推奨フォルダ構成:
rag-study/
├── learning-plan.md          ← このファイル
├── phase1-rag/
│   ├── 01-chunking/
│   ├── 02-embedding/
│   ├── 03-parent-document/
│   ├── 04-hybrid-search/
│   ├── 05-reranking/
│   ├── 06-lost-in-middle/
│   ├── 07-query-transformation/
│   └── 08-adaptive-rag/
├── phase2-agent/
│   ├── 01-langgraph-basics/
│   ├── 02-self-reflection/
│   ├── 03-error-feedback/
│   └── 04-multi-agent/
└── phase3-evaluation/
    ├── 01-ragas/
    ├── 02-langsmith/
    └── 03-mem0/
```
