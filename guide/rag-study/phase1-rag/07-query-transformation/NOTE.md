# 1-7. Query Transformation（HyDE / Multi-Query） — 学習ノート

## 概念

ユーザーの質問はそのまま検索に使うには曖昧すぎることが多い。
質問を**変換**してから検索することで精度を改善する。

## 3つの手法

### HyDE（Hypothetical Document Embeddings）

```
ユーザーの質問 → LLMが「仮の回答」を生成 → 仮の回答で検索
```

- 仮の回答は文書と同じ文体になるため、ベクトル空間で文書に近くなる
- 事実質問に強い。LLMが間違った仮回答を出すと逆効果
- 例: 「速いやつ」→ 「FastAPIは高性能なWebフレームワークで...」→ この文で検索

### Multi-Query

```
ユーザーの質問 → LLMが複数の視点に展開 → 各クエリで検索 → 結果を統合
```

- 1つのクエリでは拾えない文書を別のクエリで拾える
- 幅広い情報収集に向いている。検索回数が増えるため遅い
- 例: 「速いやつ」→ 「高速なフレームワーク」「パフォーマンス比較」「ベンチマーク」

### Step-Back Prompting

```
ユーザーの質問 → LLMが一段抽象化 → 抽象化した質問で検索
```

- 具体的すぎるクエリの検索漏れを防ぐ
- 「なぜ」「どのように」系の質問に向いている
- 例: 「FastAPIが速い理由」→ 「Python Webフレームワークの特徴と比較」

## 各手法が効くケースと逆効果なケース

| 手法 | 効くケース | 逆効果なケース |
|---|---|---|
| HyDE | 事実質問、技術的な質問 | LLMの知識外の質問（最新ニュース等） |
| Multi-Query | 幅広い情報収集 | ピンポイントで1文書を見つけたい場合（ノイズ増） |
| Step-Back | 原因・理由を問う質問 | 具体的な手順を知りたい場合（抽象化しすぎ） |

## 重要な気づき

- Query TransformationはLLM呼び出しが必要 → レイテンシとコストが増える
- まず Hybrid Search + Reranking を試し、それでも精度が足りなければ導入を検討する
- HyDEとMulti-Queryは併用も可能（HyDEで生成した仮回答 + 元のクエリでMulti-Query的に検索）
