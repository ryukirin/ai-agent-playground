# 1-6. Lost in the Middle 対策 — 学習ノート

## 概念

LLMはコンテキストの**先頭と末尾に注意力が集中し、中間の情報を忘れる**。
これは「Lost in the Middle」問題と呼ばれる（2023年のStanford論文で実証）。

```
LLMの注意力の分布:

  高 ████                    ████ 高
       ████              ████
         ████          ████
           ████      ████
  低          ████████         低
      先頭    ← 中間 →    末尾
```

## なぜ起きるのか

- Transformerの自己注意（Self-Attention）は位置に応じたバイアスを持つ
- 先頭のトークンはすべてのトークンからAttentionを受けやすい
- 末尾のトークンは最新の情報として重み付けされやすい
- 中間のトークンは前後から埋もれやすい

## 4つの対策パターン

| パターン | やり方 | 効果 |
|---|---|---|
| 関連度順（デフォルト） | 検索スコア順にそのまま並べる | 正解が中間に埋もれる可能性あり |
| 先頭配置 | 最も重要な情報を先頭に置く | ✓ 効果的 |
| 末尾配置 | 最も重要な情報を末尾に置く | ✓ 効果的 |
| LongContextReorder | 重要度の高い情報を先頭と末尾に交互配置 | ✓ 自動で最適化 |

## 最も効果的な対策

1. **Rerankingで件数を絞る（1-5で学習済み）** — 渡す情報自体を減らすのが最も確実
2. **LongContextReorder** — LangChainで `LongContextReorder` を使って自動的に並べ替え
3. **重要情報を先頭/末尾に明示配置** — プロンプト設計で対応

## 重要な気づき

- Lost in the Middleは**コンテキスト窓が大きくなるほど深刻**になる
- 10件程度なら影響は小さいが、50件以上渡すと中間の情報はほぼ無視される
- **Rerankingで上位5件に絞る → Lost in the Middle 問題がそもそも発生しない**
- つまり1-5（Reranking）と1-6（Lost in the Middle）は密接に関連している
- プロンプトに「すべてのコンテキストを注意深く読んでください」と書いても効果はない
