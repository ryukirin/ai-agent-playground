# 3-3. Mem0 / 長期記憶レイヤー — 学習ノート

## 概念

エージェントにセッションを跨ぐ長期記憶を持たせ、パーソナライズされた応答を実現する。

## 3つの記憶レイヤー

```
Short-term Memory（短期記憶）
  = 会話履歴（現在のセッション内）
  LLMのコンテキスト窓に入る範囲
         ↓ 重要な情報を抽出
Long-term Memory（長期記憶）
  = ユーザーの嗜好、過去の決定
  Mem0がベクトルDBに保存
         ↓ 必要な時に検索
次の会話で活用
  「前回Pythonを希望されましたね」
```

## 記憶のカテゴリ

| カテゴリ | 内容 | 例 |
|---|---|---|
| **preference** | ユーザーの好み・スタイル | 「型ヒント付きコードが好き」 |
| **project** | 取り組んでいるプロジェクト | 「FastAPIでバックエンド構築中」 |
| **context** | 過去の会話の文脈 | 「認証機能の実装で困っていた」 |
| **fact** | ユーザーの事実情報 | 「データサイエンティスト」 |

## Mem0 vs 簡易実装

| | SimpleMemory (SQLite) | Mem0 |
|---|---|---|
| 検索 | キーワード (LIKE) | ベクトル検索（意味で検索） |
| 抽出 | 手動で追加 | LLMが会話から自動抽出 |
| 更新 | 手動 | 自動で統合・更新 |
| コスト | 無料 | LLM API必要 |

## Mem0の基本操作

```python
from mem0 import Memory

m = Memory.from_config(config)

# 追加（LLMが自動で重要情報を抽出）
m.add("会話内容", user_id="user_001")

# 検索（ベクトル検索）
memories = m.search("関連クエリ", user_id="user_001")

# 回答生成時に記憶を注入
prompt = f"ユーザーの記憶: {memories}\n質問: {query}"
```

## 重要な気づき

- 毎回ゼロから会話が始まるエージェントは実用性が低い
- 長期記憶があることで「前回の続き」「ユーザーの好みに合わせた回答」が可能になる
- 記憶の管理（古い情報の更新・削除）も重要。古い記憶が混乱を招くことがある
- プライバシーの配慮: ユーザーが記憶の削除をリクエストできる仕組みが必要
